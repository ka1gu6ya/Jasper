# TrailNote · 旅行工作台

给「徒步 + 城市」旅行用的一站式记录工具：**逐日行程、预定聚合、装备重量、花销账本**。
本地优先，装到手机主屏后**断网也能用**——山里的那几天照样能查装备、记账。

![四个模块](icons/icon-512.png)

---

## 怎么跑起来

**方式一（推荐）**：双击 `start.command`，会自动开服务器并打开浏览器。

**方式二**：命令行

```bash
cd trailnote
python3 -m http.server 8123 --bind 127.0.0.1
# 然后打开 http://127.0.0.1:8123/
```

> 为什么不能直接双击 `index.html`？
> 这是 PWA，用了 ES 模块和 Service Worker，浏览器在 `file://` 协议下会拒绝加载。
> 必须走 `http://`，所以需要一个本地静态服务器。除了 `python3` 不需要装任何东西。

### 装到手机主屏（像 App 一样用）

1. 手机和电脑连同一个 Wi-Fi
2. 电脑上把服务改成对局域网开放：`python3 -m http.server 8123 --bind 0.0.0.0`
3. 手机浏览器访问 `http://<电脑的局域网 IP>:8123/`
4. Safari → 分享 → **添加到主屏幕**；Chrome → 菜单 → **安装应用**

装好后会全屏运行、有独立图标，**并且离线可用**（首次打开后资源就已经缓存到本地了）。

## 四个模块

### 1. 行程 — 逐日安排
按旅行日期自动生成每天一张卡片。每天可以填：

- 距离（km）、累计爬升（m）、最高海拔（m）、地形
- 当天的主题和备注（水源、营地、危险点）
- 带时间的安排条目（交通 / 徒步 / 活动 / 餐饮 / 住宿 / 备忘），可勾完成

### 2. 预定 — 集中管理
航班、火车、包车、住宿、徒步许可、餐厅都能记：确认号、服务方、起止时间、地点、金额、状态（已确认 / 待确认 / 已取消）。

- **从邮件导入**：把航空/酒店确认邮件的正文粘进来，自动识别航班号、确认号、日期时间、金额、出发到达地，填进表单由你核对。**不会静默写入**，一定经过你的确认。
- **导出 .ics**：一键把全部预定塞进系统日历，手机上到点会提醒。
- 确认号可一键复制。

> 关于「同步」这件事说清楚：航司和酒店没有给个人开发者用的公开 API，
> 全自动拉取做不到。所以这里做的是 **80% 自动（邮件解析）+ 100% 可手动兜底 + 日历导出**。

### 3. 装备 — 带重量的清单
这是和普通清单最不一样的地方：**按背包客的行业口径拆成三份重量**。

| 概念 | 含义 |
|---|---|
| **基础重量 Base** | 除穿戴、消耗品以外的全部装备 |
| **消耗品 Consumables** | 食物、水、气罐——会在行程中减少 |
| **穿戴 Worn** | 身上穿的、手里拿的，不计入背负 |
| **背负重量 Pack** | = 基础 + 消耗品 |
| **Skin-out** | = 基础 + 消耗品 + 穿戴（人 + 全部装备） |

基础重量会对照国际通行档位给判断：

- `< 4.5 kg` 超轻量 Ultralight
- `4.5 – 9 kg` 轻量化 Lightweight
- `9 – 13.6 kg` 传统负重 Traditional
- `> 13.6 kg` 重装 Heavy

另外还有：按类别的小计与条形对比（一眼看出该砍哪块）、打包勾选进度、
**常用装备库**（下次出行一键取用）、**从其他行程整体复制**。

### 4. 花销 — 多币种账本
- 快捷记账：填金额、选类别、写备注，回车即记
- 多币种：每笔可以选币种，按你设定的汇率折算成本位币汇总
- 预算对照：已用百分比、剩余 / 超支
- 分类占比、按日分组、每日小计

## 多人出行：成员、归属、分摊

行程里可以加**同行成员**（名字 + 角色，角色随便写：领队 / 协作 / 财务 / 家属…）。

入口有三处：概览页标题下的「添加同行成员」、装备页的「设置成员」、花销页结算卡右上角。

加满 **2 人**之后，界面会多出这些：

**装备 — 按「谁背」拆重量**
- 每件装备多一个「谁背」选项（也可以选「公共 / 未分配」）
- 汇总卡下面多一块「每人背负」：每个人背了多少、几件，以及还有多少没分配
- 装备列表每行右侧显示归属人的头像缩写

这样你能立刻看出「阿哲只背了 1.1kg，我背了 10.8kg，得重新分一下」。

**花销 — 谁付的、谁分摊**
- 每笔账可以指定「付款人」
- 勾选「谁一起分摊」（默认全选），按人数均摊
- 全都不勾 = 个人支出，不参与结算
- 快捷记账栏会多一个付款人下拉，记账时顺手就能选对

**分摊结算**（花销页）
自动算出每个人的「已付 / 应摊 / 净额」，并给出**最少转账次数**的结算建议，例如：

```
小林 → 我  ¥641.00
阿哲 → 我  ¥381.00
```

多币种会先折算成本位币再算，避免日元人民币混在一起。

> 这是「一个人记录全队」的模式：你在自己手机上把所有人的账记好，结算结果发到群里。
> 想做到每人各记各的、实时合并，需要后端同步（见下方「预留同步接口」）。

## 分享行程（只读）

把一趟行程变成一个链接，发给同行的人。对方用手机浏览器打开就能看到
**行程、预定、装备清单（含重量）、花销概况**——但改不了。

入口：顶部工具栏的 **分享图标**。

### 为什么需要接一个数据库

只读链接必须有个地方放快照。这里用 **Supabase**（免费额度对个人基本用不完）。

### 四步接上（约 5 分钟）

1. **注册** [supabase.com](https://supabase.com)，新建项目（Region 选 Singapore / Tokyo，国内快一点）
2. **建表**：项目里打开 `SQL Editor`，把仓库里的 `supabase.sql` **全文**粘进去，点 Run
3. **拿密钥**：`Project Settings → API`，复制 `Project URL` 和 `anon public`
4. **填进去**：打开 `js/config.js`

```js
export const SUPABASE = {
  url: 'https://xxxx.supabase.co',
  anonKey: 'eyJhbGciOi...',   // anon public key
};
```

刷新页面，再点分享就能生成链接了。

> **本项目当前已经配好了**（`yqsnabbpmvnigapbfqej`），你不需要再填。
> 想换项目或换账号时，改这两个值即可。

### 安全模型（为什么 anon key 可以放在前端）

| 东西 | 在哪 | 作用 |
|---|---|---|
| `token` | 分享链接里 | 谁拿到谁能看 |
| `edit_key` | **只存在你自己设备上** | 用来更新 / 停止分享 |
| `anon key` | 前端代码里 | 公开的，只能调用三个 RPC |

`supabase.sql` 里**没有给 `shared_trips` 表任何直接读写权限**，只暴露三个 RPC。
所以别人就算拿到你的 anon key，也**列不出你分享过哪些行程**——必须知道具体 token 才行。
`edit_key` 在数据库里存的是 bcrypt 哈希，库被拖走也反推不出明文。

详细策略见 `supabase.sql` 顶部注释。

### 几个已经踩过的坑

- **`gen_salt does not exist`**：Supabase 把 `pgcrypto` 装在 `extensions` schema 里，
  函数的 `search_path` 必须写成 `public, extensions`，只写 `public` 会调不到 `crypt` / `gen_salt`。
  当前 `supabase.sql` 已经改好，如果你是从旧版升上来的，把整份重跑一遍即可（幂等，不丢数据）。
- **编辑密钥只存在本机**：`edit_key` 放在浏览器的 localStorage 里（跟着导出备份走）。
  清缓存或换设备后，你就没法再更新 / 撤回那条旧链接了——链接本身还能看。
  所以：**重要行程记得导出备份**。
- **本机生成的链接别人打不开**：`localhost` / `127.0.0.1` 的链接只有你自己能开。
  部署到云端后再生成，域名会自动变成对的（界面上会有提醒）。

### 更新和停止

- 改完行程后，点「更新链接内容」，链接不变，对方刷新就能看到新版（版本号会 +1）
- 「停止分享」会立刻删掉快照，已经拿到链接的人也打不开了
- 链接里的内容是**发布那一刻的快照**，不是实时同步

### 仓库公开前想一下

`js/config.js` 里的 anon key 是设计成公开的，泄露不算事故：表没有直读权限，RPC 也需要 token。

但它确实意味着**任何拿到这个 key 的人都能创建分享条目**（猜测 token 不行，但可以自己造 token 塞数据）。
个人使用无所谓；如果你要把仓库公开、又担心有人刷你的存储，可以在 SQL Editor 里加一个行数上限：

```sql
-- 可选加固：最多保留 300 条分享，超过就拒绝新建
create or replace function public.shared_trips_quota() returns trigger
language plpgsql as $$
begin
  if (select count(*) from public.shared_trips) >= 300 then
    raise exception '分享数量已达上限';
  end if;
  return new;
end $$;

drop trigger if exists shared_trips_quota on public.shared_trips;
create trigger shared_trips_quota before insert on public.shared_trips
for each row execute function public.shared_trips_quota();
```

### 不接 Supabase 会怎样

什么都不影响。本地记录、离线、导出备份照旧，只是点分享会显示配置指引。

### 没有 Supabase 账号时想先试

```bash
python3 tools/mock-supabase.py        # 起一个假后端，端口 8126
```

然后临时在 `index.html` 的 `app.js` 之前加一行注入配置（或直接用浏览器控制台）：

```html
<script>
  window.__TRAILNOTE_SUPABASE__ = { url: 'http://127.0.0.1:8126', anonKey: 'mock' };
</script>
```

这个 mock 实现了和 `supabase.sql` 完全一致的接口形状，用来验证整条链路。

## 难度指数怎么算的

不是随便打个「困难」标签，而是一个可以横向比较的数字：

```
单日强度 = 距离 × (1 + 爬升/1000 × 1.5) × 负重系数 × 地形系数 × 海拔系数

负重系数 = 1 + max(0, 背负kg - 6) × 0.05
地形系数 = 成熟步道 1.0 / 碎石乱石 1.15 / 灌木野路 1.2 / 雪线冰川 1.35 / 铁索攀爬 1.45
海拔系数 = 最高海拔 > 3000m 时，1 + (海拔 - 3000) / 10000
```

把每天的强度加起来：

- `< 30` 轻松 · `30–70` 适中 · `70–120` 挑战 · `120–200` 困难 · `> 200` 严苛

举例：15km / 800m 爬升 ≈ 33 强度，和体感基本对得上。
系数是经验值，如果你觉得偏松或偏紧，改 `js/calc.js` 里的 `dayEffort` 就行。

## 数据存在哪 / 怎么备份

- 全部数据存在**当前浏览器的 localStorage** 里（键名 `trailnote.state.v1`），不上传任何服务器。
- **换设备 / 清缓存前请备份**：`数据与设置 → 导出备份`，会下载一个 JSON 文件；
  在新设备上 `导入备份` 即可。
- 存储写满时会有提示（浏览器一般给 5–10 MB，够记录很多趟行程）。

## 部署到云端

这是个纯静态站点，没有后端，所以任何静态托管都能跑。只有两个硬性要求：

- **必须 HTTPS** —— Service Worker 和「安装到主屏」的前提（localhost 例外）
- 别让托管平台改掉 `.js` / `.css` 的 MIME 类型（主流平台都不会）

### 平台怎么选

| 平台 | 免费额度 | 国内直连 | 需要备案 | 评价 |
|---|---|---|---|---|
| **Cloudflare Pages** | 带宽不限，500 次构建/月 | 一般可用（走香港/新加坡节点） | 否 | **首选**，最省心 |
| **GitHub Pages** | 1GB 站点 / 100GB 月流量 | 不稳定，时快时慢 | 否 | 自己用、发给朋友够用 |
| Vercel | 100GB 带宽/月（限业余项目） | 多数情况连不上 | 否 | 国内不推荐 |
| Netlify | 100GB 带宽/月 | 多数情况连不上 | 否 | 国内不推荐 |
| 腾讯云 EdgeOne Pages | 有免费额度 | 快（可用国内节点） | 国内节点绑域名要备案 | 面向国内访客时值得考虑 |
| 阿里云 OSS / 腾讯云 COS | 按量计费 | 快 | 要备案，且默认域名不能直接建站 | 有备案域名再考虑 |
| Gitee Pages | — | — | — | 个人免费版基本已停，别指望 |

> 免费额度各平台随时会调整，动手前看一眼官网。
> 另外 Cloudflare 免费版在中国大陆没有节点，速度取决于就近的境外节点，**能开但不算快**；
> 如果访客主要在国内且很在意速度，备案 + 国内云是最优解。

### Cloudflare Pages（推荐，5 分钟）

1. 把 `trailnote/` 目录里的内容推到一个 GitHub 仓库（让它就是这个仓库的根目录）
2. Cloudflare Dashboard → **Workers & Pages** → Create → **Pages** → Connect to Git
3. 选仓库，构建配置：
   - Framework preset：`None`
   - Build command：**留空**
   - Build output directory：`/`
4. Deploy，拿到 `xxx.pages.dev`，可以再绑自己的域名（免费，自动签证书）

### GitHub Pages

1. 把 `trailnote/` 里的文件放到仓库根目录（或者放进 `/docs`）
2. 仓库 **Settings → Pages** → Source 选 `Deploy from a branch` → `main` / `root`（或 `/docs`）
3. 等一两分钟，访问 `https://<用户名>.github.io/<仓库名>/`

### 关于子路径部署

已经处理好了，不用改任何路径：所有引用都是相对路径，`manifest` 的
`start_url` / `scope` / `id` 都是 `./`，并且放了 `.nojekyll` 防止 GitHub Pages 用 Jekyll 处理文件。

实测把整个目录放到 `/repo/` 这种子路径下，页面、图标、Service Worker
（作用域正确落在 `/repo/`）都正常。

### 部署完要接受的一件事

**部署只解决「别人能打开这个网址」，不解决数据同步。**
每个人的浏览器里有自己独立的一份数据。换设备、换浏览器、清缓存，数据都不会跟着走。

所以：**定期用「数据与设置 → 导出备份」存一份 JSON**。

## 关于「预留同步接口」

这一版是本地优先，但同步的位置已经留好了，不是画饼：

- 所有写操作都只经过一个入口 `store.commit(mutator, meta)`
- 每次写入会递增 `meta.rev`、标记 `dirty`、往 `oplog` 追加一条操作记录
- `js/store.js` 里有一个 `LocalOnlyAdapter`（空实现），接口形状是：

```js
const adapter = {
  id: 'my-backend',
  label: '云端同步',
  supportsSync: true,
  async push(ops) { /* 把本地 oplog 推上去 */ },
  async pull(since) { /* 拉取 lastSyncedAt 之后的变更 */ },
};

sync.use(adapter);   // 就这一行，界面不用改
```

接上 Supabase / PocketBase / 自建服务时，只需要实现这两个方法，
再处理一下冲突（建议按实体 `updatedAt` 后写胜出）。UI 层完全不用动。

├─ css/app.css             全部样式（含深色模式、响应式）

└─ js/
   ├─ app.js               外壳：路由、侧边栏、数据管理
   ├─ store.js             数据层：持久化、迁移、同步适配器接口
   ├─ calc.js              纯计算：重量、难度、汇率、ICS、邮件解析
   ├─ ui.js                组件：图标、弹窗、表单、提示

   ├─ sync.js              分享：发布 / 读取 / 撤回

   └─ views/

## 有意没做的事

- **不做自由排版编辑器。** Notion 的自由度对行程规划是负担，结构化表单 + 好看的时间轴更好用。
- **不做全自动预定同步。** 没有可用的 API，承诺了也做不到。
- **暂时不做实时共同编辑。** 只读分享已经能用（一个链接看全队行程），
  但「几个人同时改同一份」还需要账号体系和冲突处理，属于下一阶段。
- **不做地图和照片。** 先把「计划 → 执行 → 记账」这条主线做顺。

## 已知限制

- 数据跟着浏览器走，换浏览器 / 清缓存就没了 —— 请定期导出备份。
- 汇率要手动维护（数据与设置 → 汇率设置），没接实时汇率。
- 邮件解析是启发式的，中文邮件识别准确率较高，英文模板可能需要手动补字段。
- 分享是**只读快照**，不是实时协作。对方看到的是你最后一次发布的版本。
- 共同编辑（每人各自登录、实时合并）还没做，需要「账号 + 成员表 + 冲突处理」，
  在 `js/sync.js` 和 `supabase.sql` 上继续加。
